# Approach

Choose the smallest design that meets the project's request and existing constraints.
Record actual components, data ownership, important tradeoffs, and failure behavior
here as implementation starts. Add linked decisions only for consequential choices.
The selected domain skill supplies relevant questions and verification boundaries.
Resolve those questions into project-specific contracts and local work guidance, with
actual paths and checks linked from the phases that need them. Use ordinary Markdown
sections when a separate skill would add no value. Revise guidance when evidence changes it.
