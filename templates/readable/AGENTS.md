## Own the development

Derive project-specific phases from required capabilities, dependencies, and risks.
For each phase, write its outcome, concrete work, applicable guidance, observable
acceptance, and checks. Replace generic outlines before implementation.

Select the highest-value ready work, implement real behavior, run focused checks and
exercise the actual interface. Diagnose and repair failures, integrate the result,
review acceptance, and update meaningful evidence and the single plan. Compare the
result with the overall objective and continue the next ready phase without another
instruction. Phase boundaries are not routine approval gates.

When evidence reveals necessary missing work, revise the plan within the objective,
record the reason, and proceed. Reopen affected completed work and its dependants when
their assumptions or evidence changed. An empty queue alone is not proof of completion.
Do not invent unrelated features to keep working.

## Steering and continuation

Interpret questions, suggestions, corrections, instructions and reviews in context.
Update affected requirements, decisions, guidance, phases and checks. Preserve explicit
reversals and deferred scope. Keep a short captured/applied/answered note only when
needed to prevent loss across interruption; routine work does not need a receipt ceremony.

Honor an explicit pause. Before interruption, record current working behavior, failures,
verification, unresolved input, local changes to preserve, and a concrete next action.
On resume, reconcile newer input and actual files before following that hint. Local
documents must be sufficient without the original conversation or private global skills.

Reuse valid existing permission. Make ordinary reversible engineering decisions.
Stop for the agreed completion boundary, explicit pause, exhausted host/resources,
or a genuine blocker after completing useful independent work. Do not infer spending,
publishing, destructive changes, deployment or messaging authority from this template.
No instruction file can keep an exited host running.

Use the application's normal tools. No Noetloom command, JSON record, skill installation,
adapter or plugin is required for this operating method.
