# Progress and continuation

Keep this short and current. It is a resume aid; the plan remains the work queue.

- Current objective, completion boundary, authority and exact workspace/worktree;
  branch/revision when available, plus actual owner paths.
- Current phase and what actually works; completed actions versus responses delivered.
- Latest relevant verification with source identity, failures and unresolved issues.
- Important workspace changes to preserve.
- Material assumptions, accepted steering and outstanding responses.
- Pause state and the concrete next action within existing authority.
- Task-owned jobs/workers, identifiers, exclusive file ownership, unfinished outputs,
  artifacts and state to inspect before restarting or reassigning work.
- Successful recovery method and failed retrieval routes to avoid repeating.

For consequential steering that could be interrupted, note the input and whether it is
captured, applied to its owners, and answered to the user. Preserve reversals and deferrals.
Do not mark a response delivered merely because implementation changed. Routine messages
and internal edits do not each require a separate record.

Update this note at useful boundaries and before a known context limit. Keep private
host/session pointers in task-owned host state when appropriate, and omit credentials,
unrelated conversation and raw tool dumps from public records.

After compaction or handoff, read this note first, reconcile newer input, verify the exact
workspace and running work, then read relevant owners. Retrieve history only for missing
context and switch methods after bounded retrieval fails. Continue authorized ready work
without repeating completed actions or requesting another "continue". An old checkpoint
cannot override a newer correction or an explicit pause.
