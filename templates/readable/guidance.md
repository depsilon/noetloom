# Project working guidance

Write only guidance this application actually needs. This can be a section in the
project owner instead of another file. Replace prompts with concrete local contracts.

For each recurring or consequential work boundary, record when the guidance applies,
the relevant components and data, rules that must hold, failure handling, verification,
and the evidence needed to finish. Link it from the entrypoint and affected phases.

Examples of questions to resolve: which inputs are accepted; who owns stored data;
how duplicate identifiers, partial writes or migrations behave; how interfaces report
errors; which accessibility or resource constraints apply. Resolve these for the project
instead of copying every generic domain checklist.

Use original, independently understandable instructions. Do not depend on private global
skills or host discovery. Add a native skill wrapper only if useful for the chosen host.
