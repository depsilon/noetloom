# Verification and completion evidence

Map each required behavior to an ordinary application command or observable scenario.
Write the expected outcome and important failure cases. Choose checks that would fail
for a plausible broken implementation; generated files and marker checks are not proof.

For meaningful verification, retain the date, relevant source revision or inputs,
command/scenario, result and limitations. A concise table is enough. Clearly distinguish
what was actually run from proposed procedures or unavailable external checks.

Run focused checks while implementing, repair failures, then broaden checks for shared
contracts and integration. Exercise a representative complete user journey before
declaring the objective complete. Revalidate affected evidence after source, acceptance
or check changes; preserve unrelated and historical results.

Record completed phase outcomes and remaining external boundaries here or in the plan's
named completion owner. No Noetloom command or machine-readable record is required.
