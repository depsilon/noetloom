# Noetloom repository grounding

Apply to Noetloom repository work, including a checkout at a different path or a worktree.
Confirm the current root and Git status, read [AGENTS.md](../../../AGENTS.md), then run
`python3 -B -m noetloom status` from that root. Read the selected item's referenced sources
and the project skill appropriate to the task; do not load the entire archive.

The [charter](../../../docs/charter.md) owns intent. The
[plan](../../../docs/state/plan.json) owns priority. The user's current instructions own
authority. Resume existing work after compaction and preserve prior decisions and grants.
The roadmap does not grant publication or compute-spend authority.

Noetloom studies an original learned foundation architecture with persistent state and
selective computation. It has no required LLM subsystem or prescribed human cognitive
taxonomy. Keep hypotheses, learned capability, hand-written controls, and evidence distinct.

Use global SL-DH engineering, research, verification, and subagent routing when applicable.
Repo-local research, evaluation, and artifact skills add only project-specific constraints.
The primary owns scientific judgment and final acceptance; verify bounded leaf outputs.

Keep bulky outputs outside the checkout and cloud-synced folders under the declared
resource policy. Finish the selected item with appropriate executable evidence, a scoped
decision, and an accurate next step. Avoid turning past results into permanent instructions.
