---
name: noetloom-bootstrap
description: Establish project-specific phases and guidance, then drive an autonomous build using Noetloom's readable method.
---

Locate the distribution's BOOTSTRAP.md: from this directory, go up three directories
in the repository or two in a portable plugin. Read that entrypoint and its linked
operating method. They define the complete baseline; no Noetloom command or native
skill discovery is required.

Inspect the actual brief and target workspace. Establish the objective, constraints,
existing authority, exclusions, and completion boundary. Derive concrete implementation
phases and relevant local guidance from the requested capabilities and their risks.
Review coverage, dependencies, failure paths, and meaningful verification before work.
An outline or a generic implementation item is not a project plan.

Use ordinary local documents and application tools. Optional templates can reduce
typing; rewrite them for the actual project. Use the Python helper profile only when
requested or appropriate to an established project; read docs/helpers.md for it.
Its bootstrap sentinel must be replaced by real phases before implementation.

Create the application in the requested workspace, outside this reference distribution
unless maintaining an explicit example. Preserve existing architecture, instructions,
licenses, and unrelated changes when adopting a project. Read the project's resulting
entrypoint, then drive implementation, testing, repair, and integration across phases
until the agreed boundary. Do not stop after generation or ask for routine phase approval.
